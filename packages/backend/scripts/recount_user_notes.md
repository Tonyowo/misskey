# 个人主页帖子数核查与修复

个人主页的帖子总数是该用户在本站数据库中现存的全部帖子数，包括回复、转发、引用、频道帖子和所有可见性。访问者看到的列表仍受权限和筛选条件限制，不能用公开列表的长度覆盖总数。

本地账号的历史偏差会在新版本首次启动时自动重算。更新代码并构建后，先完全停止旧后端和所有队列 worker，再启动新版本；不要滚动替换仍会延迟更新计数的旧进程。修复在 HTTP 服务和 worker 启动前完成，日志会输出 checked（检查账号数）、mismatched（不一致账号数）和 repaired（修正账号数），只更新不一致的计数。

检查涵盖全部本地账号，包括零帖子账号；远程账号的缓存不代表对方站点的完整历史，因此不在此重算范围内。修复不会改动帖子、可见性、关注数、活动时间或其他用户资料。

发帖入库与计数增加现在在同一个数据库事务中完成，不再依赖异步后处理。现有删帖事务只在真正删掉记录时扣减一次。自动修复使用数据库锁协调新主进程，成功后在主 Redis 中保存无过期时间的标记 `maintenance:user-note-counts:2026-10-v1`；普通重启跳过历史扫描。失败时启动中止，下次重试。数据更新在一个事务中提交；标记丢失或写入失败时重复执行也不会重复增减。

如需查看全站本地账号中究竟有多少账号不一致，在已构建的部署目录执行只读核查（可以在服务运行时执行）：

```sh
cd /home/ubuntu/misskey/packages/backend
node scripts/recount_user_notes.mjs
```

输出 `checked`、`mismatched`、`repaired`；默认 repaired 为 0，不写数据库或 Redis，也不输出帖子正文和数据库密码。

通常无需手动修复。若需再次对账，完全停止所有后端和 worker 后执行：

```sh
node scripts/recount_user_notes.mjs --apply --maintenance
```

手动修复不设置自动启动标记，下一次启动仍可安全复查。修复只改变派生的整数计数；回退代码不会恢复错误旧计数。重新启动并刷新主页后应看到当前正确总数。
